Antes do Código: Engenharia de Requisitos

APC — Atividade Prática de Classe · UC III (Qualidade e Testes de Sistemas) · Aula 01
Nome:
Turma:

Você já usou algum app ou site que travava, ou fazia algo que ninguém esperava? Isso quase nunca é só "erro de programação" — na maioria das vezes, o problema nasceu antes de qualquer linha de código, porque ninguém parou pra entender direito o que o sistema precisava fazer. Essa etapa se chama Engenharia de Requisitos, e nenhum sistema sério deveria ser construído sem ela.

Requisito é qualquer condição que um sistema precisa ter pra atender uma necessidade real de quem vai usá-lo. Existem três tipos:

Funcional — o que o sistema DEVE FAZER (uma ação). Ex.: "permitir login com matrícula e senha."
Não funcional — COMO o sistema deve se comportar (uma qualidade). Ex.: "responder em até 2 segundos."
Restrição — um limite externo que o projeto precisa respeitar. Ex.: "funcionar nos computadores antigos da escola."

Parte 1 — Diagnóstico
A escola quer criar um sistema de chamada online, pra substituir a chamada em papel. Para cada frase abaixo, escreva na coluna "Tipo" se é Requisito Funcional (RF), Requisito Não Funcional (RNF) ou Restrição (R).
#FraseTipo
1O sistema deve permitir que o professor marque presença ou falta de cada aluno.
2O sistema deve funcionar mesmo com a internet lenta do laboratório da escola.
3O sistema deve gerar automaticamente um relatório de frequência mensal por aluno.
4O sistema precisa rodar nos computadores antigos que a escola já tem, sem exigir upgrade.
5O sistema deve carregar a lista de alunos em até 3 segundos.
6O sistema deve permitir que o aluno justifique uma falta anexando um atestado.
7O sistema deve seguir o layout visual já usado no site da escola.
8O sistema deve impedir que um aluno altere a própria frequência.
